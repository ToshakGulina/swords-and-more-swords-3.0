# Клиентские ресурсы: совпадения путей с образцами Mojang

Проверены файловые пути всех resource pack 1.6, 2.8.8, 2.8.14 относительно двух официальных образцов Mojang. ZIP образцов, commit, SHA и ограничения описаны [здесь](manual-vanilla-override-review.md). Сравнение по относительному пути — **не** доказательство, что Minecraft заменяет соответствующий файл целиком или объединяет словари, что версия автора совпадает с образцом, либо что пользователь увидит именно такую картинку. Файлы 1.6 сопоставлены с теми же более поздними внешними ориентирами без утверждения об их историческом соответствии.

| Аддон | Файлов RP, без каталогов | Путей, встречающихся в каждом образце | Побайтово совпадают с каждым образцом |
|---|---:|---:|---:|
| 1.6 | 56 | 4 | 0 |
| 2.8.8 | 184 | 26 | 4 |
| 2.8.14 | 184 | 26 | 4 |

В эти числа входят и служебные `manifest.json`/`pack_icon.png`: совпадение имени внутри разных пакетов не доказывает конфликт этих метаданных. Все общие пути, размер, SHA-256 и признак побайтового равенства — в [машинных данных](../data/vanilla-resource-diff.json), как и хэши остальных RP-файлов аддона. Для выбранных JSON записаны полные изменившиеся значения client description/render controllers, а для атласов, блоков, звуков и UI — ключи аддона, количество ключей только образца и точные отличия общих ключей. Для lang сравнение сохраняет **списки всех значений повторного ключа**, без предположения о приоритете. JSON5 с повторными ключами отклоняется, в lang дубли не удаляются. Ключи объектов неупорядочены, массивы упорядочены, `1 == 1.0`; это не попиксельная сверка и не отрисовка.

Воспроизведение после получения двух ZIP по ссылкам в источниках:

```sh
python tools/build_vanilla_resource_diff.py \
  --reference-119 /путь/bedrock-samples-v1.19.40.2.zip \
  --reference-120 /путь/bedrock-samples-v1.20.30.1.zip
```

Проверяются хэши внешних ZIP. В таблицах key-map учитываются только выбранные явно указанные в JSON пути (`texture_data`, `sound_definitions`, `entity_sounds.entities` и т. д.), не любые динамические вызовы. Учитываются только точные и чувствительные к регистру имена файлов/ключей. Файлы, которых нет в образце по тому же пути, не называются отсутствующими в игре.

## Слои атласов, локализации и UI

- В 2.8.14 `textures/item_texture.json` содержит **42** ключа `texture_data`; в обоих образцах в выбранной карте **234**, ни один из 42 ключей аддона не совпадает с образцом. В 1.6 — **26**, тоже без общих точных ключей. Это не доказывает, как движок объединяет атласы; локальные связи предметов и PNG описаны в [визуальном индексе](item-visual-index.md).
- `blocks.json` содержит `format_version` и шесть `effect99:` ключей в 2.8.14; в 2.8.8 также `effect99:fake_ice`. В `terrain_texture.json` соответствующие шесть/семь `texture_data`-ключей не совпадают с ключами образцов. Полный перечень в данных. Меньший файл аддона сам по себе **не** доказывает исчезновения всех остальных ванильных блоков/текстур.
- `sounds/sound_definitions.json` в обеих 2.x содержит три ключа `wolf_sword.howl`, `wolf_sword.distant_howl`, `ghost_sword.wailing`; ни один из них не найден среди ключей `sound_definitions` двух образцов. `sounds.json` задаёт четыре `entity_sounds.entities` — `entity:alpha_wolf`, `entity:centella`, `entity:mountable_slime`, `entity:slime_king` — без общих ключей с выбранными картами образцов. Фактическое воспроизведение и правила объединения не доказаны.
- `texts/en_US.lang` 2.x имеет **627 различных ключей**, 1.6 — **26**; нет совпадающих точных ключей ни с одним образцом в этой простой построчной модели. Образцы содержат **9469/10071** различных ключей. Повторный `entity.entity:ghost.name` в обеих 2.x имеет значения `§lGhost` и `§l§fGhost`, без вывода о приоритете. Совместная загрузка и локализационный fallback не установлены; [локальные строки и UI](ui-localization-index.md).
- В `ui/how_to_play_screen.json` 2.x **84** top-level ключа; в образцах **146/148**. У каждого образца с аддоном четыре общих точных ключа: один одинаков, три различаются — `how_to_play_screen@how_to_play_common.screen_base`, `selector_stack_panel`, `section_content_panels`; ещё 80 ключей есть в аддоне, но не в выбранном образце. Из этого нельзя вывести, пропадут ли стандартные разделы в загруженной игре. Размеры шести `textures/ui/how_to_play_button_*.png` в аддоне — **16×16**, в образце 1.19 — **15×15**; байты различаются, пиксельное или визуальное соответствие не проверялось.

## Клиентские определения существ

- `entity/enderman.entity.json` аддона добавляет texture alias `red_enderman: textures/entity/enderman/red_enderman`; соответствующий `red_enderman.tga` локально существует. Render controller `controller.render.enderman` меняет texture `Texture.default` на `Array.textures[query.variant]` с массивом `[Texture.default, Texture.red_enderman]`. Сама базовая `textures/entity/enderman/enderman.tga` побайтово совпадает с обоими образцами. Это соответствует декларации variant 0/1, описанной в [разборе сущности](manual-vanilla-entities-2.8.md), но не доказывает визуальное переключение.
- Оба `entity/witch.entity.json` и `entity/witch.v1.0.entity.json` добавляют alias `grass_witch: textures/entity/grass_witch`; локальный PNG существует. `controller.render.witch` и `.v1.0` вместо `Texture.default` объявляют `Array.variants[query.variant]` с default и grass_witch. Идентичность alias ещё не доказывает, какая версия client definition загрузится или какой вариант будет выбран.
- `entity/player.entity.json` добавляет к образцам aliases текстур, геометрии, материалов и анимаций для Ultra Instinct, Wolf, Ghost, Mermaid и Blaze; дополнительные render-controller элементы имеют Molang-условия. Сравнение содержит полные исходные изменённые объекты, а [индекс клиентских анимаций](client-animation-index.md), [геометрии](client-geometry-index.md) и [эффектов](client-effects-ledger.md) фиксирует их локальные определения. Работа переменных и видимость не проверены.
- Остальные совпадающие с обоими образцами по байтам файлы 2.x: `render_controllers/default.render_controllers.json`, `textures/entity/slime/magmacube.tga`, `textures/entity/slime/slime.png`. Побайтовое совпадение этих отдельных файлов не доказывает идентичность всего render-графа или итогового изображения.
